Git i GitHub to dwie różne rzeczy
Git
  • program na Twoim komputerze
  • zapisuje historię zmian w plikach
  • działa bez internetu
  • darmowy, open source
GitHub
  • serwis internetowy: github.com
  • przechowuje kopie repozytoriów
  • pull requesty, issues, code review
  • podobne: GitLab, Bitbucket

Jak to działa
Trzy miejsca, przez które przechodzą zmiany
Working directory
Katalog roboczy
Tu edytujesz pliki jak zwykle.
git add
Staging area
Poczekalnia
Tu wybierasz, co trafi do commita.
git commit
Repository (.git)
Repozytorium
Trwała historia wszystkich commitów.
git status w każdej chwili pokazuje, które pliki są zmienione, które czekają w poczekalni, a które Git dopiero zauważył.
5
Praktyka
Pierwsze repozytorium krok po kroku
# 1. Utwórz folder i zamień go w repozytorium
$ mkdir moj-projekt && cd moj-projekt
$ git init
# 2. Utwórz plik README.md i sprawdź stan
Linux / macOS / Git Bash
$ touch README.md
Windows (PowerShell)
PS> New-Item README.md
$ git status
# 3. Dodaj plik do poczekalni (git add . dodaje wszystko)
$ git add README.md
# 4. Zapisz migawkę z opisem
$ git commit -m "Git init and README.md"

Porządek
Plik .gitignore: czego nie śledzić
# zależności i pliki wynikowe
node_modules/
build/
*.o
*.exe
# sekrety i ustawienia lokalne

  • Git pominie pasujące pliki przy git add.
  • Nigdy nie commituj haseł ani kluczy API — zostają w historii nawet po usunięciu.

11
Gałęzie
Komendy do pracy z gałęziami
git branch
lista gałęzi (gwiazdka = aktualna)
git switch -c nowa-funkcja
utwórz gałąź i przejdź na nią
git switch main
wróć na gałąź main
git merge nowa-funkcja
scal wskazaną gałąź z aktualną
git branch -d nowa-funkcja
usuń gałąź, która jest już scalona
W starszych poradnikach zobaczysz git checkout -b nazwa — robi to samo co git switch -c nazwa.
12
Gałęzie
Konflikt scalania i jak go rozwiązać
<<<<<<< HEAD
print("Witaj!")
=======
print("Cześć!")
>>>>>>> nowa-funkcja
# góra: Twoja gałąź, dół: scalana gałąź
  1. Git zatrzymuje scalanie i oznacza plik.
  2. Otwórz plik i zostaw właściwą wersję albo połącz obie.
  3. Usuń znaczniki <<<, === i >>>.
  4. git add plik, potem git commit.
Rezygnacja ze scalania: git merge --abort

15
GitHub
Wysyłamy projekt na GitHub
Na github.com kliknij New repository, nadaj nazwę i utwórz puste repozytorium (bez README). Potem w terminalu:
$ git remote add origin https://github.com/login/moj-projekt.git
$ git branch -M main
$ git push -u origin main
# -u zapamiętuje origin/main, kolejne razy wystarczy samo git push
Logowanie: hasło do konta nie działa w terminalu. Użyj tokena (Personal Access Token), klucza SSH albo GitHub CLI: gh auth login.

Gdy coś nie działa
Typowe błędy i jak z nich wyjść
fatal: not a git repository
Jesteś poza repozytorium. Przejdź do folderu projektu (cd) albo zrób git init.
! [rejected] … (fetch first)
Na GitHubie są nowsze commity. Najpierw git pull, potem git push.
Authentication failed
Hasło nie działa w terminalu. Użyj tokena, klucza SSH albo gh auth login.
Zła wiadomość commita
git commit --amend -m "Nowa treść" — tylko przed wysłaniem na GitHub.
